## Technical Details

### Root Cause
Windows Korean locale uses CP949 (MS949) as default encoding, but:
- Python scripts output UTF-8
- JSON files should be UTF-8
- subprocess.run() defaults to system encoding (CP949)

### Solution Pattern
Always specify `encoding='utf-8'` for:
1. `subprocess.run()` calls
2. `open()` for JSON files
3. `open()` for text files

## Best Practices Learned

### Windows Encoding Issues
1. Always specify `encoding='utf-8'` in subprocess.run()
2. Use `encoding='utf-8'` when opening JSON files
3. Add `errors='replace'` for graceful fallback

### JSON File Management
1. Ensure all JSON files are UTF-8 encoded
2. Use `ensure_ascii=False` for Korean characters
3. Validate encoding before committing to git

### Debugging Encoding Errors
1. Check browser console for API errors
2. Test endpoints with curl: `curl -s http://localhost:5001/api/endpoint`
3. Validate JSON files: `python -m json.tool file.json`
